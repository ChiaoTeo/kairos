# Decision 0017：运行方案、运行实例与运行中心

- Status: Accepted
- Date: 2026-08-25
- Scope: Workbench 策略管理、Launch、System Observe、项目共享服务与支撑进程
- Extends: [Decision 0014](0014-unified-textual-workbench.md)

## Context

现有产品同时用 `Launch` 表示可重复使用的配置、用户选择的策略运行对象和正在运行的记录。
`LaunchRegistryApplication` 保存的实际是带有 `instance_id` 的运行实例，但 System Observe 和
Workbench 仍把这些记录称为 `launches` 或“正在运行的 Launch”。策略入口还包含系统观测动作，
“服务与进程”又能进入 Launch 详情，因此配置管理、实例生命周期和项目运行观测之间缺少稳定边界。

这种混用会产生三个问题：用户无法判断一次停止针对运行方案还是某次执行；历史失败实例可能被当作
当前运行状态；服务维护无法清楚表达它会影响哪些活动实例。

## Decision

### 1. 产品使用策略、运行方案和运行实例三个对象

- `Strategy`（策略）是可执行的策略逻辑或版本。
- `Run Plan`（运行方案）是当前 `Launch` 配置表达的可重复运行意图。它选择 Strategy、mode、账户、
  Market scope、Risk、Execution、Capital、通知和安全参数。
- `Run Instance`（运行实例）是运行方案的一次实际执行，由 `launch_id / instance_id / mode` 唯一定位。

产品文案不再把运行实例称为“正在运行的 Launch”。底层 `kairos launch` 命令、配置目录和现有 Python
类型暂时保持兼容；新增代码必须根据语义使用 `run_plan` 或 `run_instance` 命名，不能继续用裸
`launches` 表示实例集合。

启动运行方案会创建新实例。重启是停止当前实例后从同一运行方案创建另一个实例，不复用实例身份。

### 2. “策略管理”拥有期望配置和实例历史

Workbench 的策略入口命名为“策略管理”，负责：

- 列出、创建、编辑和校验运行方案；
- 从运行方案创建运行实例；
- 查看该方案的活动实例和历史实例；
- 从具体实例查看状态、组件、日志、时间线和报告；
- 对整个实例执行停止或恢复。

策略管理不提供项目级服务清单、System Observe 快照或支撑进程操作。Strategy、Account、Market、
Risk、Execution 和 Capital 的业务事实仍由各自 owner 持有。

### 3. “运行中心”是当前项目运行事实的操作投影

原“服务与进程”入口命名为“运行中心”。它回答“当前项目里什么正在运行、是否健康、相互有什么
依赖、哪里需要处理”，并按以下作用域展示：

```text
运行中心
  -> 活动运行实例
  -> 项目共享服务
  -> 支撑进程
```

运行中心只展示当前运行拓扑，不列出运行方案草稿、未运行配置或历史实例。活动实例包括启动中、
运行中、降级、无响应和停止中的实例；已停止、已完成和纯历史失败记录不属于活动实例。

活动实例在运行中心中的用户场景是全局值守、异常发现、共享服务影响分析、孤儿资源诊断和运维交接。
选择活动实例后进入策略管理所使用的同一个实例详情，不建立第二套实例状态或生命周期实现。

### 4. 运行中心按 owner 边界限制动作

- 项目共享服务展示运行方式、健康、日志和依赖它的活动实例；停止或重启前执行依赖安全检查。
- 活动实例只提供摘要和“进入实例详情”，整个实例的停止或恢复由实例详情调用 Launch Application。
- 支撑进程只提供状态、日志和技术证据，不伪装成普通业务服务。
- Instance-owned Account、Risk、Execution、Capital 和 Market 不在运行中心获得局部启停入口。

System Observe 聚合 System-owned 进程事实和运行实例注册事实，但不取得业务状态所有权。它的公开结果
使用 `active_instances`，不再用 `launches` 指代实例集合。

`kairos observe` 是运行中心的 CLI 投影，而不是 Launch 历史导航或命令推荐器。默认交互模式复用运行
中心并持续刷新；`--once` 返回一个时间点的机器可读事实，包括 `overall_status`、`shared_services`、
`active_instances`、`support_processes`、`observed_at` 和读取错误。它不返回历史实例、Market 业务快照
或根据“最近一条注册记录”猜测的 `next_action`。具体业务事实和动作继续进入相应 owner 或实例详情。

### 5. 当前状态与历史证据分离

项目总体健康只由当前项目共享服务、支撑进程和活动实例决定。历史完成、停止或失败的实例继续保存在
运行方案的实例历史和审计证据中，但不得永久降低当前项目健康状态。

`current` 或 `active` 必须表示经运行状态确认的当前目标；“最近注册实例”如需持久化，应显式命名为
`latest`，不得用时间上的最新记录冒充仍在运行的实例。

## Consequences

- 用户从“策略管理”表达运行意图，从“运行中心”观察实际运行事实。
- 正在运行的对象统一称为运行实例，启动和重启的身份语义更加明确。
- 共享服务页面能够用活动实例解释依赖影响，同时不会复制实例控制界面。
- System Observe 不再因历史实例状态永久显示项目降级。
- 底层 Launch 兼容命名可以渐进迁移，但新接口和集合名称必须保持运行方案与运行实例的区别。
